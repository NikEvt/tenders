# Чего не хватает в API

Файл вёлся при сборке клиента: каждый экран, которому не за что было
зацепиться, показывал честное пустое состояние со ссылкой сюда, а место в коде
помечалось константой `API_GAP`.

**Все разделы закрыты.** Константы `API_GAP` и компонент `ApiGapNotice` удалены
за ненадобностью — искать по ним больше нечего.

- **волна 5** (правка по `FIX_BRIEF.md`) — категорийные сортировки, порядок
  списком ключей, курсор по составному ключу и `GET /tenders/groups` с
  агрегатами по группам.

Что было сделано, по волнам:

- **волна 1** — похожие закупки, фасеты и гистограмма цены, курсорная
  пагинация, сортировка каталога, перечень дат со сводками, заголовок
  `X-Request-Id`;
- **волна 2** — чтение и управление сохранёнными фильтрами, сохранение
  отредактированной спецификации, воронка проверки по этапам;
- **волна 3** — границы чанков и поиск по фрагментам документации. Текст чанка
  стал дословным срезом `document_texts.content`, поэтому цитату из вердикта
  теперь есть где подсветить;
- **волна 4** — сводное состояние сервисов, очереди с лестницей повторов и
  разбором недоставленных, журнал выгрузок, воронка обработки документов,
  настройки, расширенный профиль, событийный след закупки.

## Переход «находка → место в документе»

Появилось вместе с новым движком отбора. Находка несёт цитату и смещение
совпадения **внутри цитаты**, но не ссылается на чанк — а именно по `chunk_id`
прежде строилась ссылка «показать источник» в вердикте.

Чтобы вернуть переход, нужен либо `chunk_id` у находки, либо смещение находки в
`document_texts` (`source_offset` в базе уже есть — наружу не отдаётся).

Пока перехода нет, вердикт показывает цитату с подсветкой и называет файл со
страницей. Якорь не выдумывается: подсветить наугад хуже, чем не подсветить.

## Осталось за пределами API

Два пункта, которые нельзя было закрыть правкой шлюза.

### Фасет «способ определения поставщика»

Единственное, что не поехало вместе с остальными фасетами. Причина не в API: в
`tenders` нет такой колонки, а `law_type` краулер проставляет константой
`44-FZ` — фасет по нему был бы одним столбцом на всю выдачу.

Нужна работа в краулере: `epNotificationEF2020` несёт способ определения
поставщика, его надо разобрать в `notification_mapper` и сохранить отдельной
колонкой. После этого фасет добавляется в `SqlFacetsRepository` одной строкой.

### Название региона

Сортировка и группировка по региону идут по коду субъекта: в `tenders` есть
`region_code` и нет названия. Порядок получается кодовый, а не алфавитный, и
подписи направлений в реестре сортировок говорят об этом прямо («по возрастанию
кода»), а не врут про «А → Я». Имя субъекта подставляет клиент по справочнику
`REGIONS` в `shared/lib/format.ts` — справочник неполный, только те субъекты,
которые реально настраивают в `EIS_REGIONS`.

Чтобы порядок стал алфавитным, нужна колонка с названием: справочник субъектов
в базе и `region_name` в `notification_mapper`. После этого в `SORT_COLUMNS`
меняется одна строка, а `dirLabels` в реестре — на «А → Я».

### `POST /monitoring/crawler/runs` — «выгрузить заново»

У краулера нет ни HTTP-интерфейса, ни потребителя событий: в
`services/crawler/presentation/` лежит только `cli.py`. Публиковать событие
некуда, поэтому эндпоинта нет — вместо него на странице выгрузок показывается
журнал запусков и код отказа ЕИС.

Чтобы кнопка появилась, нужно: событие `CrawlRequested` в
`libs/shared/contracts/events.py`, подписка `EventConsumer` в краулере и
публикация из шлюза через outbox. Outbox здесь транспорт, а не чужой агрегат,
так что правило единственного писателя не нарушается.
